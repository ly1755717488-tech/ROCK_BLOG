{% note info %}
一句话：推理模型的「想得越久越安全」并不成立——长段无害推理会稀释拒绝倾向，而暴露出来的思考过程本身也成了可被利用的接口。
{% endnote %}

## 从 LLM 到 LRM

大型语言模型正在演变成大型推理模型（LRM）：通过扩展推理时的推理能力，也就是常说的思维链（CoT），把复杂任务拆成一步步的逻辑序列。数学、编程、科学推理这些领域的表现因此明显提升。

产品侧为了让人信任输出，往往把这段思考展示出来。透明度上去了，但也把内部结构摆到了外部输入面前。

这里有一个流传很广的假设：花更多时间「思考」，模型应该能更好地评估自己回答的安全性与伦理影响，所以推理增强的模型理当比前代更安全。近来的研究给了相反的证据。

## H-CoT：劫持的是「安检之后」的流程

H-CoT（Hijacking Chain-of-Thought）不是靠话术说服模型，而是针对思考过程本身做结构化注入。

把模型处理请求的过程粗略分成两段：

1. **安全判断（Justification）**：这个请求安全吗？是否违反原则？要不要直接拒绝？
2. **任务执行（Execution）**：确认无害之后，规划怎么一步步给出答案。

正常链路是先过第一段，再进第二段。H-CoT 的思路是伪造一份「已经通过判断」的上下文，让模型以为安检结束了，直接落到任务执行上。它不与安全判断正面冲突，而是绕到它后面去。

{% note warning %}
这里只讲机制，不展开具体构造方式。可操作的模板一旦公开，等于给所有人发一把钥匙，而这对防守方没有额外价值。
{% endnote %}

论文报告的成功率很扎眼：顶级模型的拒绝率可以从 98% 以上降到 2% 以下，而且方法跨模型可迁移。这说明问题不在某一家模型的提示词写得不够好，而在更底层的设计取舍。

## 拒绝稀释：为什么想得越久，越容易松口

更有意思的是「过度思考」这一侧。

研究发现，当模型先生成越来越长的无害推理（比如解一道很复杂的逻辑题），它内部的拒绝信号会被逐渐削弱。等到结尾出现一个巧妙嵌入的有害请求时，模型维持一致拒绝的能力已经下降。这个失效模式叫**拒绝稀释（refusal dilution）**。

用 Transformer 的视角看，可以取最后一个输入 token 的残差激活，往「拒绝」方向上投影，得到一个标量：

```text
R = <h_last, v_refusal>
```

R 越大，越倾向拒绝；R 越小，越容易照做。长段良性推理会把 R 往下拉。也就是说，安全信号不是恒定的，它会被上下文长度和内容稀释。

这解释了一个反直觉的现象：安全对齐在短问短答上看起来很好，一旦把对话拉长、把任务包装成连续推理，同一套对齐就可能失效。

## 对工程和产品的启示

### 别把「想得久」当成安全措施

推理时长和安全性没有单调关系。把安全判断放到输出侧做独立校验，比寄希望于模型在长推理里自我约束可靠得多。

### 展示思维链是有代价的

展示 CoT 提升了透明度和可调试性，但也把内部结构暴露给了外部输入。至少要区分「给用户看的摘要」和「模型真实的推理过程」，不要把原始推理直接当成产品界面的一部分。

### 红队要覆盖长上下文场景

只测单轮短请求，会高估对齐效果。测试集里应该包含长段无害前置任务、任务延续型措辞、多轮渐进式铺垫。这些都是公开研究已经指出的方向。

### 安全判断要能独立成立

如果安全判断只存在于「模型愿不愿意想」这个层面，它就会被上下文状态影响。更稳的做法，是把它做成链路上一道独立的、不依赖前文长度的检查。

## 收尾

H-CoT 和拒绝稀释指向同一件事：安全不是模型的一个属性，而是整条链路的结果。上下文长度、展示方式、判断时机，任何一环的假设变了，结论都会变。

研究这些机制的价值，不在于找一条能绕过谁的捷径，而在于知道防线在哪里薄。
