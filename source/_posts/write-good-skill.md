核心目标：用结构化的 Skill 设计与强制闭环，解决 AI Agent 执行不稳定、经验无法沉淀、长对话容易偏离规则，形成效率持续倍增、能力越用越强的正向循环。

## 一、Skill 设计的核心三原则

这是底层指导思想，贯穿结构、执行、迭代：

1. **结构服务于内容**  
   流程框架、规则设计都要围着实际任务转，拒绝为了流程而流程，不做形式化的规则堆砌。

2. **激活优于存储**  
   规则的价值在于被触发执行，而不是存放在文档里积灰。好的 Skill 会设计大量激活节点，让规则在需要时自动生效，而不是靠 Agent 主动回忆。

3. **结构可复用，内容禁止预制**  
   通用的执行框架、复盘流程、兜底逻辑可以复用；具体场景下的执行内容、输出结果不能提前固化，要保留灵活性。

## 二、Skill 在 Agent 能力体系中的定位

- **RAG**：外挂知识库，让回答有依据，解决知识不足。
- **MCP**：调用工具、访问系统、对接外部服务，解决行动边界。
- **Skill**：更像整个流程的大脑，决定该怎么做：规划路径、调度工具、把控质量、沉淀经验。

相比普通 Prompt，Skill 的优势是**按需加载、渐进式披露**：路由判断当前场景，精准触发对应 Skill，只暴露当前需要的规则，避免信息过载。它是精准工具，不是大而全的通用指令。

## 三、长对话稳定性：强制再读

### 典型痛点

同一会话里经常出现 Agent 越用越飘：第一轮还严格遵循 Skill，到第三轮、第五轮就开始凭直觉输出，读过的 `SKILL.md` 被抛在脑后，质量大幅波动。

### 核心原因

这往往不是模型能力不够，而是 Skill 里缺少**强制再读的钩子**。长对话里上下文会被压缩、遗忘，没有触发点提醒 Agent 重读规则，就会偏离规范。

### 设计目标

在任务切换、模块交付、长对话中途等关键节点，设置强制重读规则，让 Agent 保持严谨，避免过度自信、脱离规则自行其是。

## 四、Skill 的两大核心职能

1. **兜底保障**  
   覆盖边界场景、异常、错误路径。遇到不确定问题或偏离流程时，给出明确处理规则，防止执行失控。

2. **多种工具协同**  
   调度不同工具在正确节点介入，形成完整链路。避免工具各自为战、调用时机混乱，让 RAG、MCP、代码执行、文件操作配合起来。

## 五、核心机制：完整任务闭环与强制 AAR 复盘

这是方法论的重中之重：解决 Agent 做完就忘、经验无法沉淀。用三层设计让复盘成为不可跳过的环节。

### 1. 任务闭环的核心理念

Agent 容易把「代码写完、功能跑通、测试通过」当成终点。在这套方法里，这只完成了一半，还差复盘沉淀。

完整闭环必须走完三步：

1. **主体工作完成、验证通过**：完成业务目标，输出符合要求的成果，这只是基础交付。
2. **执行 30 秒 AAR 扫描**：快速回答 4 个自检问题，判断是否需要更新规则。
3. **结果处理**：4 个问题全是否，任务正式结束；有是，就按标准流程更新规则库。

{% note tip %}
不能只管干活不管沉淀。每做一个任务都要给规则库施肥，让系统越用越聪明，而不是每次从零踩坑。
{% endnote %}

### 2. 30 秒 AAR 快速自检：4 个问题

复盘不用写长篇报告，扫这 4 个问题即可：

- 有没有用到新的协作模式 / 约定？
- 有没有遇到很耽误时间的新坑？
- 有没有因为缺某条规则走了弯路？
- 有没有发现旧规则已经不准了？

可以跳过复盘的唯一范围：纯格式化调整、改注释、更新版本号、无新收获的重构。除此之外，所有任务都必须自检。

### 3. 借口拦截表：把偷懒理由提前堵死

只定规则不够。任务压力大、时间紧时，Agent 会自己找借口跳过复盘。把真实场景里最常用的 5 种借口和反驳写死：

| Agent 常用借口 | 核心反驳逻辑 |
| --- | --- |
| 任务小，没必要做 | 小任务才最容易藏坑；30 秒的事，纠结的功夫都做完了 |
| 等会话结束一起补 | 回头就忘，必须收尾就做，不能攒批处理 |
| 用户赶时间 | 越赶时间越容易踩坑，越要做复盘 |
| 这经验我已经知道了 | 记录是给以后的 Agent 看的，不是给现在的你 |
| 规则里已经有了 | 那 10 秒就能扫完，做了比争论快 |

{% note warning %}
这张表只能添加**真实抓到过的借口**，不能凭空脑补。瞎编的借口 AI 根本不会用，反而会稀释拦截效果，让它换个说法就能绕过去。
{% endnote %}

### 4. 红线兜底：碰到立刻叫停

流程约束、借口拦截都可能被突破时，这 4 条不可触碰，碰到任何一条必须停下：

- 心里冒出「这次 AAR 就算了」：这是规则松动的起点，开了先例后续就会频繁跳过。
- 说任务完成了，但没做 30 秒扫描：流程缺失的不合格交付，必须补做。
- 坑点只写进参考文档，没更新到工作流检查项：经验没沉淀进执行流程，等于白踩坑。
- 同类 bug 修了第二次，还没更新规则：复盘机制失效，正在重复踩坑。

这些红线必须同时写进「薄壳文件」。长对话里完整工作流可能被压缩丢掉，薄壳文件是守住规矩的最后防线。

## 六、整体设计逻辑

三层递进：

1. **强制流程**：复盘是任务必经环节，没做就不算完成。
2. **借口拦截**：把跳过复盘的常见理由提前堵死。
3. **红线兜底**：出现突破规则的苗头立刻叫停。

最终目的只有一个：让 Agent 没法偷懒跳过复盘，把每一次任务的经验固化成规则，技能体系越用越稳、越用越准。
