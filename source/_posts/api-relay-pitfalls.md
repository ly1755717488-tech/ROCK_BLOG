{% endnote %}

## 实测踩坑归纳

### 1. 模型智商情况

- Plus 渠道的 GPT6 普遍降智。
- 0.2 倍率低价渠道基本全部降智，能力不及 Gemini3.8 Flash。
- Pro 低价渠道参差不齐：部分账号降智、部分正常，类似抽奖。
- 少数 0.2 / 0.25 倍率站点模型表现稳定，能通过鹈鹕测试。
- 高倍率渠道稳定性尚可，但性价比不如官方正价 API。

很多中转商家不会标注模型降智情况，存在掺水，用户付费拿到的是阉割版模型。

### 2. 售后痛点

遇到降智问题退款困难，商家往往无法解决模型降智。  
小额充值（如 5 元）维权耗时，得不偿失。

### 3. 倍率与缓存率信息不透明

缺少中转站汇总平台，倍率、缓存率、稳定性无法实时查询。商家常虚标倍率，例如标题写的是大额充值才有的低倍率。

缓存率对实际成本影响极大。以 95% 缓存率为基准：

| 实际缓存率 | 相对基准成本 |
| ---------- | ------------ |
| 95% | 1.00 倍（基准） |
| 90% | 1.49 倍 |
| 80% | 2.46 倍 |
| 70% | 3.44 倍 |

很多站点不标注缓存率，运行时缓存不稳定，原本宣传的超低倍率会暴涨，还伴随卡顿、模型降智。

### 4. 结论

在缺少权威平台统一检测模型智商、倍率、缓存率之前，中转渠道性价比不如官方订阅，踩坑概率高、耗费大量测试时间。

## 1. 倍率是什么

OpenAI 官方 API 有固定单价（比如 GPT6 输入 $X / 1k token，输出 $Y / 1k token）。  
中转站是中间商，从官方拿额度，加价 / 减价卖给你。

$$
\text{倍率} = \text{中转单价} \div \text{官方原价}
$$

例子：官方 1k 输出 token 0.1 美元，中转站卖你 0.02 美元 / 1k token → 倍率 0.2。

- 倍率 ＜ 1：比官方便宜；倍率越小越便宜。

{% note info %}
商家宣传的 0.2 倍率，很多时候是建立在高缓存率前提下的纸面数字，不是你真实使用的成本。
{% endnote %}

{% note danger %}
坑点：商家标题写 0.2 倍率，但那是大额充值才有的价格；小额充值倍率更高；甚至模型是降智阉割版，却按 GPT6 的倍率收费。
{% endnote %}

## 2. 缓存率是什么

中转站会做请求缓存：

- 当有人问了一模一样的问题 + 一样的参数，商家不调用 OpenAI 官方 API，直接把上次保存好的回答返回给你。这叫命中缓存。
- 命中缓存：商家不消耗官方 token 额度，成本几乎为 0。
- 未命中缓存：必须调用 OpenAI 官方 API，实打实扣商家的 token。

$$
\text{缓存率} = \frac{\text{命中缓存的请求数}}{\text{总请求数}}
$$

举例：缓存率 95%。  
100 次请求里，95 次走缓存（不花钱），仅 5 次真实调用 OpenAI。

## 3. 为什么缓存率越低，你的真实成本越高

商家标价的 0.2 倍率，是假设缓存稳定 95% 算出来的纸面低价。  
一旦缓存失效、缓存率下降，真实需要消耗的官方 token 变多，你的等效实际倍率就会上涨。

以 95% 缓存率作为基准：

- 90% 缓存：实际成本是基准的 1.49 倍
- 80% 缓存：实际成本是基准的 2.46 倍
- 70% 缓存：实际成本是基准的 3.44 倍

直观理解：

> 商家宣称 0.2 倍率（前提 95% 缓存），如果实际使用缓存掉到 70%，真实等效倍率变成 `0.2 × 3.44 = 0.688`，纸面 0.2 的低价直接变成接近 0.69 倍率。

### 额外连带坑

缓存差的站点通常还伴随：

1. 大量真实请求涌向 OpenAI，商家为控成本偷偷换成降智模型；
2. 新请求排队，出现卡顿、响应慢；
3. 商家页面不标注缓存率，你无法预估真实花费，只能踩坑实测。

## 4. 简单总结

- **倍率**：中转售价相对官方原价的折扣系数，纸面价格指标。
- **缓存率**：重复问答复用旧回答的命中率，决定商家真实 API 消耗。
- 缓存越高 → 商家越少调用官方 API → 维持低倍率越容易。
- 缓存越低 → 商家大量消耗官方 token → 你实际等效成本大幅上涨，宣传的低价倍率直接失效。
